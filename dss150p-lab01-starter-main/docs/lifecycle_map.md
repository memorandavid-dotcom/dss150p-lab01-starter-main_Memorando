# Data Lifecycle Map

This document maps the end-to-end journey of each data source from its origin through ingestion, profiling, storage, and consumption in this laboratory environment.

---

## 1. Customers (`customers.csv`)

| Stage | Detail |
|---|---|
| **Origin / Producer** | CRM export — CSV flat file generated by an upstream customer-management system |
| **Raw Landing** | Local filesystem: `customers.csv` (root of repo) |
| **Ingestion Method** | Batch file load via `pandas.read_csv()` in `src/profile_sources.py` |
| **Profiling Tool** | `src/profile_sources.py` — shape, dtypes, null counts, duplicate check, min/max of numeric columns |
| **Intermediate Storage** | `data/raw/customers.csv` (copy used by profiling scripts) |
| **Schema Enforcement** | `sql/01_create_schema.sql` — `lab.customers` table in PostgreSQL |
| **Downstream Consumer** | Analytical reporting; data contracts enforced via `docs/data_contract.yaml` |
| **Expected Cadence** | Daily batch arrival by 06:00 UTC |
| **Retention / Deletion** | Raw file retained; processed rows upserted into relational staging |

---

## 2. Orders (`orders.json`)

| Stage | Detail |
|---|---|
| **Origin / Producer** | Order-management system — JSON document export |
| **Raw Landing** | Local filesystem: `orders.json` (root of repo) |
| **Ingestion Method** | `pandas.read_json()` in `src/profile_sources.py`; also served live via `local_api_server.py` |
| **Profiling Tool** | `src/profile_sources.py` — shape, nested-field detection, duplicate row check |
| **Intermediate Storage** | `data/raw/orders.json` |
| **Schema Enforcement** | Semi-structured; nested items must be flattened before loading into relational tables |
| **Downstream Consumer** | Operational dashboards, order-fulfilment analytics |
| **Expected Cadence** | Real-time / hourly |
| **Retention / Deletion** | Full document retained; normalized records loaded to downstream warehouse |

---

## 3. Products (`products.parquet`)

| Stage | Detail |
|---|---|
| **Origin / Producer** | Analytical lakehouse / data lake — Parquet columnar export |
| **Raw Landing** | Local filesystem: `products.parquet` (root of repo) |
| **Ingestion Method** | `pandas.read_parquet()` (requires `pyarrow`) in `src/profile_sources.py` |
| **Profiling Tool** | `src/profile_sources.py` — strongly typed schema, zero-null validation, min/max statistics |
| **Intermediate Storage** | `data/raw/products.parquet` |
| **Schema Enforcement** | Self-describing binary schema; strict type enforcement enforced at read |
| **Downstream Consumer** | Product catalogue analytics, inventory reconciliation |
| **Expected Cadence** | Weekly batch |
| **Retention / Deletion** | Versioned Parquet snapshots retained in `data/raw/` |

---

## 4. REST API (`http://localhost:8000/api/orders`)

| Stage | Detail |
|---|---|
| **Origin / Producer** | Local classroom API server (`local_api_server.py`) serving the first 100 orders from `orders.json` |
| **Raw Landing** | HTTP GET response; snapshot written to `data/raw/api_snapshot.json` |
| **Ingestion Method** | `src/inspect_api.py` — `requests.get()` with 20-second timeout; UTC retrieval timestamp logged |
| **Profiling Tool** | `src/inspect_api.py` — status code, content-type, record count, sample record keys |
| **Intermediate Storage** | `data/raw/api_snapshot.json` |
| **Schema Enforcement** | JSON key inspection; no strict schema enforcement at API layer |
| **Downstream Consumer** | Pipeline integration tests; order-volume monitoring |
| **Expected Cadence** | On-demand / real-time |
| **Retention / Deletion** | Snapshot overwritten on each run; timestamp recorded in inventory |

---

## 5. PostgreSQL (`support_tickets` table)

| Stage | Detail |
|---|---|
| **Origin / Producer** | Seed script: `seed_support_tickets.sql` — 250 synthetic support-ticket records |
| **Raw Landing** | PostgreSQL 16 container (`dss150p-postgres`) — table `public.support_tickets` |
| **Ingestion Method** | `psql` or pgAdmin — `\i seed_support_tickets.sql` executed against `dss150p_lab` database |
| **Profiling Tool** | `src/inspect_postgres.py` — column list, data types, nullability, row count, sample rows via SQLAlchemy |
| **Intermediate Storage** | Persisted in Docker-managed volume `dss150p_pgdata` |
| **Schema Enforcement** | DDL in `seed_support_tickets.sql`: `ticket_id INTEGER PRIMARY KEY`, `NOT NULL` constraints on `customer_id`, `category`, `priority`, `opened_at`, `status`; `resolved_at` and `assigned_agent` nullable |
| **Downstream Consumer** | Support-operations analytics; SLA reporting |
| **Expected Cadence** | Transactional / continuous |
| **Retention / Deletion** | Volume persisted across container restarts; removed only with `docker compose down -v` |
